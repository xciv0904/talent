# Career Lab 開發前盤點

盤點日期：2026-10-19。以目前 checkout 的程式碼及執行結果為準。

## 架構與基準
- React 19 / TypeScript strict / Vite 8 / Tailwind 4；React Router BrowserRouter，頁面 lazy 載入。Vercel 已有 SPA rewrite，保留原部署方式，不另建網站。
- `AppLayout` 共用導覽與鍵盤焦點；`useSyncExternalStore` 訂閱原有 localStorage 狀態。
- 修改前 `npm test`：37 個檔案、138 項測試通過。這是程式邏輯基準，並非所有舊 UI 已經過瀏覽器驗證。

## 題庫、天賦與推薦
- `quick-discovery.ts` 實際匯出 25 題核心＋10 題補充，共 35 題，並非 45 題。保留所有題目。
- `assessment-engine` 驗證回答，按題型證據品質及選項信號建立 observations / opportunities。
- `talent-engine` 依有效支持與可測量機會正規化 20 項基礎能力；能量、興趣、信心獨立處理。信心依覆蓋、多方法一致性及證據品質。
- `composite-talent-engine` 加權組成能力；最低組成信心及證據量限制複合結論。
- `integration-engine` 串接測驗、基礎與複合天賦、偏好向量、職涯推薦與分類。
- `career-match-engine` 權重：能力 .35、興趣 .18、工作方式 .15、環境 .15、價值 .10、可轉移技能 .07；環境超出容忍度另扣分，覆蓋程度調整偏好信號。不修改。
- 既有職業資料含穩定 ID、核心任務、技能、環境、入職條件及短實驗；公開職業群組為另一呈現層，不應新增重複職業。
- 入職距離引擎已比對教育、技能、經驗、證照、作品、語言、執照；現有 UI 誠實顯示個人背景未蒐集時「尚未估算」，不將預設背景當實際距離。

## 已有功能與缺口
| 功能 | 實際狀況 | 保護方式 |
|---|---|---|
| 測驗、基礎／複合天賦、結果、方法 | 已接引擎且有測試 | 不動計分及題庫 |
| 職業庫、推薦、一般比較 | 已有 route 與資料 | 保留 `/careers`、`/career/:careerId`、`/compare` |
| 20 分鐘體驗、反思 | 已有四步引導與 feeling/preference 儲存；未對作品客觀評分 | 保留 `/experiments`，新任務另存 |
| 轉職距離 | 引擎完成；個人背景 UI 不完整 | 實驗室引用一般準備需求並註明限制 |
| 十年故事、多存檔、決策分支、工作產出 | 尚未實作 | 新增純函數引擎與職業內容設定 |
| 探索證據、版本、雙時間軸、報告 | 舊體驗有反思，尚無共用證據層 | 新增獨立探索層，保留來源與日期 |

## 儲存與相容
- 原 namespace `career-discovery-state`，schema 6；解析支援舊 2–5 版，依計分版本可能要求補驗證。沿用現有遷移邏輯。
- 原資料包含 answers / talentProfile / careerResults / experiments / reflectionResults / navigatorState / betaFeedback 等，禁止寫入覆蓋。
- 實驗室新增 `career-discovery-lab` 版本化空間，讀取原測驗與短實驗僅作快照；失敗不得覆蓋未知版本／損壞存檔。需要儲存失敗提示、匯出、個別刪除與重設。

## 首版實作順序
1. 純狀態轉移、seed、條件式事件與儲存。
2. 一條端到端 Career Life，再以資料擴充六職業。
3. 可檢驗結構化任務、自由文字自我檢核、獨立主觀反思。
4. 平行存檔、歷史節點分支、比較。
5. 探索證據、分析版本、成長與可列印報告。
6. 回歸、資料遷移、手機與桌面瀏覽器驗證；將限制如實記錄。

## 盤點後採用的範圍調整

使用者於開發中要求職業不限辦公室，納入製造與服務業的發展性。因此從六種擴充為十二種，新增工業工程師、CNC 技術員、電氣技術員、飯店營運經理、旅行團務操作專員與活動營運統籌。所有內容都映射現有 ID，沒有修改職業推薦計分或新增重複職業；增加工作場域篩選及現場專用的輪值／專案分支。
