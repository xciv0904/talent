# Career Lab 實際實作規格

2026-10-19。這是既有 React / TypeScript 專案的增量功能，沒有新增外部依賴、後端、AI 金鑰或付費服務。原 25+10 題、計分引擎、schema 6、既有路由與 Vercel 設定保留。

## 入口與操作

首頁、結果頁、職業詳細頁及共用導覽均有 Career Lab 入口。未開放完整故事的職業，導向可體驗職業選擇，不假裝已有內容。

| 路由 | 行為 |
|---|---|
| `/lab` | 三模式總覽與最近未完成人生入口 |
| `/lab/life?career=<既有ID>` | 場域篩選、選職業、設定目標、節奏、名稱與個人化起點 |
| `/lab/life/:lifeId` | 六階段故事、狀態與變化原因、暫停／恢復、模擬時間軸、歷史節點分支 |
| `/lab/missions` | 可獨立進入的十二份任務，支援工作場域篩選 |
| `/lab/mission/:careerId?life=<ID>` | 選擇題、資源、排序、文字、自我檢核；可選擇綁定人生 |
| 同上加 `result=<ID>` | 重開任務結果及反思；不會重新提交獎勵 |
| `/lab/parallel` | 各人生載入、回顧、個別刪除 |
| `/lab/compare` | 選任意兩份存檔，比較十一個維度 |
| `/lab/growth` | 統計、興趣／能量、練習檢核、分析歷史、雙時間軸、資料管理 |
| `/lab/report` | 九項報告內容、原始天賦、作品與反思、來源、實驗建議、列印／JSON |

快速模式省略選項的延伸取捨提示，仍走六個年份；任務為可選獨立入口。完整模式顯示提示並在適應階段提供任務。時間為內容設計目標，尚未以實際受測者驗證時長，不是倒數限制。

## 職業內容

依使用者後續要求由六職業擴充至十二職業。每個都有三個專屬核心情境、六個年份的完整故事、一份可評估結構化產出的任務。

| 知識與商業 | `data_analyst` | 來源組成與轉換率判讀 |

| 製造與技術 | `industrial_engineer` | 組裝線瓶頸、品質與現場改善 |

## 狀態與事件規則

`Life` 含 id、careerId、name、seed、goal、mode、createdAt、updatedAt、parentId／forkAt、personal、initial、stats、history、flags、status、ending。

九項模擬尺度為 skill、energy、stress、satisfaction、money、time、autonomy、opportunity、balance，皆為 0–100 教學狀態，壓力越高負荷越高。money 是抽象資源，沒有薪資、投報或錄取機率。

Year 0／1／3 使用職業專屬背景與問題；Year 5／7 使用條件事件；Year 10 回顧並決定下一階段方向。三種選擇有不同的技能、能量、壓力、資源、機會及自主取捨，不設唯一正確故事答案。最後方向為專業深化、帶領團隊、自主與生活整合，前期狀態及事件歷史仍各自不同。

每次 `decide(life, eventId, choiceId, missions, timestamp)` 驗證目前事件與 active 狀態，回傳新物件，保存 before／after、理由及真實日期。過期事件、重複提交、暫停與完成狀態不能再次套用效果。任務不改寫天賦，可解鎖後續作品機會。

條件支援 stat 最低／最高、前置 flag、當次 goal、任務結構檢核門檻、既有天賦信心／訊號、先前同職業投入反思。符合條件事件優先；同層候選以 seed 與年份雜湊固定選取。沒有 `Math.random` 的狀態轉移；角色建立時由 crypto 產生 seed 後永久保存。

初始技能為共同練習起點，不假裝已具備職業技能。既有相關天賦能量只小幅調整模擬初始能量。其餘基礎／複合天賦、偏好、工作環境、價值觀、適配及舊實驗保留快照；提示及部分條件會引用，但不是完整人格生成器。舊人生不因後來完成測驗而悄悄改變起點。

## 任務規則

每份有目標、背景、虛構資料、操作、結構規則、回饋與範例。一般任務包括資訊分析／問題診斷、情境決策、三項資源分配、排序及短文產出，形成多步驟專案。

決策依題目明示前提檢核；資源須為 0–100 整數且總和 100，各項最低限制公開；排序為三個不重複 ID，僅評估第一前提的優先性。結構分數 = 通過規則數 / 規則總數 × 100。不是整份作品品質、能力百分位或適配機率。初始順序反向排列，使用者需要實際排序。

文字驗證 20–2000 字，自評清單獨立保存，皆不計入結構分數。範例為固定教學回饋，沒有假裝用 AI 理解產出。提交後另填興趣、成就、能量、長期意願各 1–5 及困難敘述；反思與原結果分開保存。提交 ID 防止同次重複記錄。

## 探索證據及分析版本

- A assessment：原始測驗來源及時間；起點快照保留於人生，報告引用現有原結果。
- B simulation：情境偏好、event ID、career／life ID、真實日期、模擬年份、scope，權重 .2。
- C mission：可驗證結構檢核及作品，權重 1。
- C reflection／experiment：任務自評與原短實驗自評，權重 .5，明示未評估作品品質。

權重表示證據相對可靠程度，**不做三種資料的數值混合**。規則必須有任務及反思，才提出投入／表現的支持或落差；故事再多也不能替代任務。結構 ≥70 且興趣 ≥4、能量 ≥3，提出值得現實驗證；結構高但興趣或能量 ≤2，標記落差；興趣高但結構不足，建議練習。其他情況保留待探索。

信心以「低，來源不完整」或「有限，已有產出與自評但缺跨情境驗證」呈現；首版每職業只有一份任務，反覆重做不升為高能力信心。初始天賦與作品是不同測量，不據此捏造一致性／矛盾的精確統計。

每新增重要證據保存 `AnalysisSnapshot { id, at, reason, evidenceIds, findings }`。歷史 findings 保留當時版本，不用當前結論倒填歷史。原天賦不受任何這些操作修改。

## 儲存格式、分支與恢復

```json
{
  "version": 1,
  "lives": [],
  "missions": [],
  "evidence": [],
  "snapshots": [],
  "drafts": {}
}
```

命名空間 `career-discovery-lab`。舊測驗仍用 `career-discovery-state`。支援預發布 lab v0（相同 lives／missions／evidence，補 drafts、snapshots）及 v1；未知版本、損壞 JSON、無效狀態或重複 ID 拒絕寫入並提示原資料保留。原測驗 2–6 版仍由原解析器處理。

儲存先寫 localStorage，成功後才更新快取與通知；quota／禁止儲存會顯示錯誤，不能假裝已存。原始 JSON 可直接匯出，包括無法解析的資料；還原驗證後才寫入。還原／重設與個別刪除均有 UI 確認。草稿 key 為 careerId:lifeId 或 careerId:standalone。

從某個歷史節點建立分支，取該決策之前的 history、狀態及 flags，新 id、保留 parentId／forkAt。節點前完成的任務複製到分支並標 `inheritedFrom`，維持機會條件；不另造新證據、不增加練習次數。節點之後任務不繼承。原始人生不變。刪除一條人生不刪獨立分支；該人生證據／任務／草稿及相關分析內容移除，歷史 findings 重新按留存證據計算，避免幽靈結論。

## 無障礙、報告與部署

使用原生 button／select／input／textarea、fieldset、legend、label、鍵盤焦點及 aria-pressed，進度有可讀 label，錯誤用 role=alert、選後結果有 live region。手機卡片單欄，比較表為可聚焦的水平捲動區。沿用全站 reduced-motion。報告使用 print CSS，瀏覽器列印可另存 PDF，亦可匯出包含來源的 JSON；不是伺服器產生的 PDF。

沒有改動 SEO、index metadata、CSP、SPA rewrite 或加入外連資源。`npm run dev -- --host 127.0.0.1` 本機執行；`npm test`、`npm run typecheck`、`npm run lint`、`npm run build` 驗證。部署沿用 Vercel：提交至既有部署分支後由既有專案建置，或按現有 Vercel 設定發布 `dist` 並保留 rewrite。本次交付不包含 Git push 或正式部署。

## 擴充職業

新增一筆 `LabCareer` 指向既有資料庫 ID，設定 sector、技能、三個核心情境及 MissionDefinition。新增不同於現有任務的輸入形式時擴充型別、評估器、UI、遷移與測試，不在頁面塞職業條件。共用 EventCard 的條件／影響與職業內容分離。對特殊現場職業要檢查共用事件的到場、輪班與資格脈絡，不能直接套成遠端知識工作。

## 2026-10-20：直覺作答與清楚下一步

依使用者實際回饋調整介面，不更動測量訊號、評分權重、故事選項 ID 或原始測驗紀錄。

- 原 35 題改為短情境與短選項；完整訊號契約雜湊仍為 `7473e977`。情境文案的品質檢查改成 18–50 字，不再為符合舊 35 字下限補字。文案改善不等於已完成真實受測者的理解度研究。
- 測驗先顯示短背景，再以真正要回答的問題作主標；能量題依既有兩個選擇的順序，分別提示「先選做完有精神」「再選做久最累」。頻率／經驗程度的五個選項皆有文字說明，不只顯示數字。
- 十二職業各有一段「做完能幫你了解什麼」、白話的任務背景與資料，以及 36 個核心情境共 108 個短選項。`plain-language.ts` 只處理呈現，任務選項的儲存值仍用原值，舊草稿可繼續。
- 任務分四步：選做法、分時間、排先後、寫兩句。配置可選方案，自行輸入 100 點仍保留在展開區；兩三句口語產出即可，例子與自我檢核可展開。新增步驟焦點管理，鍵盤使用者不用找新內容。原任務規則檢核保留。
- `guidance.ts` 將任務表現、同次反思、興趣、精神與長期意願分開考量；不再把不同次任務和反思平均湊成結論。以最新一份任務及同一 sourceId 的反思產生下一步。未補反思時導回該份結果的反思區。
- 建議有六個明確狀態：先試工作（task）、補上感受（reflect）、安排實際體驗（try）、先補練習（practice）、先排後／調整工作節奏（pause）、比較另一種工作（compare）。每項都有原因與可執行連結。高分不會覆蓋使用者不喜歡或不想長期做的回饋；疲憊時先確認工時、輪班與支援。
- 舊 v1 反思已存長期意願，但部分 evidence 沒有記錄此欄位；解析時只從同一 sourceId 的原反思補上缺少的 willingness，歷史分析快照不倒填。
- `TakeawayPanel` 先顯示建議、對選工作的用途與下一步；分數、規則及限制在展開區。任務結果、成長及報告使用同一套建議。故事回顧依整段選擇的次數說明偏好，不把最後一個選擇當成永久性格。
- 原測驗結果頁改成直接指出先試哪個方向、作答中看見什麼、看職缺該留意什麼，以及現在可做的體驗。方向難分時明確請使用者比較兩種日常工作，不硬排唯一第一名。

這些結論決定的是下一步探索順序，不宣稱整體職涯適合、保證成功或建議立刻離職。
